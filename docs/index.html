Yelu — a compositional
language for the AI era

A programmable configuration shell language that separates control from theories, checks at multiple stages, and is designed for human-plus-model production with verifier feedback. cmake is the first target.

yelu-cmake comparison Read the manifesto

What is yelu?

Configuration languages are the least-studied tier of the programming stack, yet they carry disproportionate operational risk. A mistyped variable in cmake silently produces ""; the fault surfaces three calls later.

Yelu is a research vehicle that asks: what if we designed a configuration language for both humans and models, with verification at every stage?

The thesis

Languages with low syntactic and semantic entropy plus strong local verification produce better model-driven generation and repair.

Read more →

The architecture

Two paired languages over a shared IR: yelu_cmake (CMake-faithful) and yelu_cmake_normal (normalized form), with to_normal/from_normal between them. 15 theory fragments per side.

Read more →

The syntax

An OCaml-Python hybrid: ML-style let bindings with a Python-ish concrete feel. ( ) blocks, ~label:value kwargs, { } records.

A quick look

Yelu's surface syntax. Full comparison on the yelu-cmake page.

( cmake_minimum_required "3.20";
  project "Tutorial" ~version:"1.0" ~languages:[CXX];

  let math : target = Target "MathFunctions" in
  add_lib math { mysqrt.cxx };

  let tut : target = Target "Tutorial" in
  add_exe tut { tutorial.cxx };
  link_lib tut { math };
  include_dirs tut {
    "${PROJECT_BINARY_DIR}";
    "${PROJECT_SOURCE_DIR}/MathFunctions"
  }
)

The same program in raw cmake would use stringly-typed names, implicit scoping, and no def-before-use checking. Yelu's checker catches typos, missing declarations, and type mismatches before cmake ever runs.

What yelu is not

  • Not a cmake replacement. cmake is the specimen, not the thesis. Yelu emits cmake; cmake still drives the build.
  • Not a build system. No runtime, no scheduler, no dependency graph. It emits text that build systems consume.
  • Not a product. A research vehicle for language design in the AI era. The artifacts test the thesis, not ship to users.
  • Not AI-only. Optimized for the human-model-verifier loop — neither for models alone nor humans alone.
